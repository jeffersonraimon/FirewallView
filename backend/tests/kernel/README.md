# Kernel differential tests

Sends the same packets through (a) the **real Linux kernel** (nftables / iptables-nft / iptables-legacy,
rootless, in network namespaces) and (b) the FirewallView simulator, and compares verdicts and NAT results.
The goal is to MEASURE the simulator/parsers/exporters against ground truth, not to fix them.

## Running

`pytest.ini` sets `addopts = -m "not kernel"`, so a plain `pytest` skips this suite. Run it explicitly with `-m kernel`
(a later `-m` overrides the default), e.g. `KD_FUZZ_SEED=2 python3 -m pytest tests/kernel -m kernel -q`.

`pytest.ini` sets `addopts = -m "not kernel"`, so a plain `pytest` skips this suite. Run it explicitly with `-m kernel`
(a later `-m` overrides the default), e.g. `KD_FUZZ_SEED=2 python3 -m pytest tests/kernel -m kernel -q`.

```
cd backend

PYTHONPATH=. python3 -m pytest tests/ -q -m "not kernel"           # the normal quick suite
```

Environment knobs: `KD_FUZZ_RULESETS` (default 30), `KD_FUZZ_PACKETS` (20 per ruleset), `KD_FUZZ_SEED` (1),
`KD_SCALE` (corpus packet multiplier, 1), `KD_OUT` (report dir, default `tests/kernel/_out/`),
`KD_SETTLE` (seconds to wait for packets, 0.30), `KD_DEBUG=1` (lab diagnostics on stderr).
Reports: `_out/report.txt` (readable) and `_out/report.json` (every mismatch + informational items).

The module skips cleanly when `unshare -Urn true` fails, `nft` / `ip` / `iptables-nft-restore` are missing, or
the platform is not Linux. Needs no root and no sudo: everything runs in `unshare -Urnm`.

## How it works

* `kernel_lab.py` (stdlib only) runs inside the user+net+mount namespace. It builds three netns:
  client `cl` (LAN) - router `rt` - server `sv` (WAN). Router interfaces are named like the
  `SimulationPacket` defaults: `ether2-lan` 192.168.1.1/24 + fd00:1::1/64, `ether1-wan` 203.0.113.1/24 +
  2001:db8:1::1/64. Client 192.168.1.50 / fd00:1::50, server 203.0.113.10 / 2001:db8:1::10.
  All cases of a run are executed by one process: per case it flushes nft / iptables-legacy / conntrack,
  loads the ruleset with the real binaries, injects crafted frames (AF_PACKET) and reads back the result.
* Observation, per packet (IPv4 `id` / IPv6 flow label = packet number):
  * forwarded: sniffed on the far side, hop limit 63 -> post-NAT src/dst/ports. Verdict ACCEPT.
  * delivered to the router itself (input, or DNAT/REDIRECT diverting a forwarded packet): the
    `inet zz_observer` table (input hook, priority 1000, only reached by packets accepted by every earlier
    chain) stores post-NAT daddr / dport in one dynamic set per packet.
  * not seen: DROP; REJECT when an ICMP error / TCP RST quoting the packet came back.
  * fresh 5-tuples (unique source ports, unique ICMP ids), conntrack state `new` only. established / related,
    tcp flags other than SYN, ICMP types other than echo-request, and the output hook are out of scope.
* Mode A (corpus): `corpus/*.nft` and `corpus/*.ipt` (iptables-save, optional `# Generated by ip6tables-save`
  section) are loaded into the kernel AND parsed with `parse_nftables_script` / `parse_iptables_script`.
  `.ipt` files run on iptables-nft and iptables-legacy (`name@nft`, `name@legacy`). A `# kd: packets=N;
  flows=...; xfail=reason` header tunes a file. Packets are generated from the parsed rules (a hit plus
  boundary variants per rule: inside / just outside of CIDRs, ranges and port ranges) plus seeded random ones.
* Mode B (fuzz, `fuzz_gen.py`): seeded random `FirewallRule` sets (subset documented in the module docstring),
  exported with `export_to_nftables` / `export_to_iptables` (the bash script runs against iptables-nft), loaded
  into the kernel, simulated on the ORIGINAL model rules.

## Comparison rules / harness adjustments (so they are not reported as simulator bugs)

* verdict: kernel ACCEPT vs simulator ACCEPT; DROP/REJECT are equal as "blocked", `reject-vs-drop` is reported
  separately (kind `reject-vs-drop`).
* NAT: post-NAT src/dst/ports must be equal. Masquerade address: the simulator uses the placeholder
  203.0.113.1 (IPv4) / 2001:db8::1 (IPv6); the topology's WAN address is 203.0.113.1, so IPv4 masquerade over
  `ether1-wan` matches exactly. Any other router address is reported as informational `placeholder`.
* The simulator does not re-route after DNAT: the harness picks `flow_type` and `out_interface` from the
  kernel's routing decision for the post-DNAT destination and re-runs when needed (listed in
  `sim.flow.reruns`). It is a harness assumption, called out as a model limitation in the triage.
* Flows that the kernel translates onto the same post-NAT tuple (SNAT collisions) are skipped
  (`nat-tuple-collision`): the kernel then changes the port or drops, which a stateless simulator cannot know.
* `ip6tables-legacy` cannot load in the WSL2 kernel (`ip6_tables` missing): such cases are skipped.
* Known inherent limitations can be marked in `KNOWN_LIMITATIONS` (test file) or with `xfail=` in a corpus header.
